Phase 6 — quantization

Decode reads every weight once per token, so its speed follows the number of bytes per weight. Quantization stores each weight in 8 or 4 bits instead of 32. This phase builds the two formats, the integer kernels that multiply them, and a way to measure how much the model got worse.

Why quantize at all?

The decode ceiling page shows that decode is a bandwidth limit: the memory bus can only deliver so many bytes per second, and every token needs all the weights. Fewer bytes per weight means more tokens per second before the bus is the limit. For SmolLM2-135M the whole model shrinks from 538 MB in f32 to 143 MB in Q8_0 and 76 MB in Q4_0 (measured).

Smaller weights cost accuracy, because each one is rounded to fewer levels. So the phase has two halves: make the bytes small, and measure what that costs.

Takeaway: quantization is a bandwidth trick, and its price is rounding error that has to be measured.

What was built?

  • Block formats. Q8_0 stores 32 weights as int8 plus one f16 scale, 34 bytes. Q4_0 stores 32 weights as 4-bit values plus a scale, 18 bytes. Both quantizers and dequantizers are in src/quant.rs and produce llama.cpp's bytes. Models are quantized in memory at load with -q q8_0 or -q q4_0.
  • Integer dot products. For decode, the activation vector is quantized to Q8_0 once per matrix product. Each block pair is then one integer dot product, using sdot, which sums four int8 products into an int32 lane per instruction. This takes the Q8_0 decode GEMV from 12 to 32 GB/s.
  • Prefill with smmla. When several tokens are processed together, smmla (from the i8mm extension) multiplies two rows by two tokens in one instruction, so each weight loaded serves two tokens.
  • Perplexity and KL mode. src/eval.rs measures perplexity on text, and KL divergence against the f32 model. It follows the same procedure as llama-perplexity, so the numbers can be compared.

Takeaway: the formats match llama.cpp, the kernels use integer math, and the accuracy is measured with the same procedure llama.cpp uses.

What is still open?

Paused on 2026-10-24 so the learning track can catch up. These are the next steps from results/phase-6.md, not results.

  • Interleave the activations once per call, not once per row pair. The current smmla kernel spends 8 instructions per block interleaving the two tokens. That cost is why Q8_0 prefill did not improve (unchanged to −5 %, measured), while Q4_0 gained 22–37 %.
  • A 4 × 4 tile, four rows by four tokens per block, instead of 2 × 2.
  • Repack the weights at load, as llama.cpp does, if the profile still shows interleaving as the cost.
  • A fresh profile. The profile in the results predates the Phase 4 scheduling fixes, so its share of spinning threads no longer applies.

llama.cpp still prefills Q4_0 2.3–2.8× faster than the new build, against 2.9–3.7× for the sdot build in the same rounds calculated from the measured table.

Takeaway: the next gains are in how the activations are laid out, not in the instruction itself.

Check yourself

Why does fewer bytes per weight make decode faster?

Each decode step reads every weight once, so the time per token is set by how many bytes must come from memory. Halving the bytes roughly halves that time, until something else becomes the limit.

What does one smmla instruction compute?

It multiplies a 2 × 8 block of int8 values by another 2 × 8 block and adds a 2 × 2 int32 result. With two weight rows and two tokens, one instruction gives four dot products, so each weight loaded serves two tokens.

Why does Q4_0 hurt SmolLM2-135M more than Qwen2.5-0.5B?

The results file gives the reason: the smaller model has fewer parameters to absorb the rounding. The costs are ×1.41 for SmolLM2 and ×1.21 for Qwen calculated.

What you should take away

Quantization trades bytes for rounding error, and the error can be measured against llama.cpp.

Q8_0 is practically lossless on both models. Q4_0 costs more, and the cost depends on the model's size.

The next speed gains come from laying out the activations and weights for the smmla tile.
