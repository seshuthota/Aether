SIMD and NEON

SIMD means single instruction, multiple data: one instruction that does the same operation on several numbers side by side. On ARM phones the SIMD instruction set is called NEON. Its registers are 128 bits wide, which is four f32s. A register is a small piece of storage inside the CPU that holds the numbers an instruction works on. This page covers the registers, the handful of instructions the engine's kernels use, and how Rust exposes them.

What does one instruction do to four numbers?

A dot product multiplies two lists of numbers pairwise, then adds up the products. A scalar add takes two numbers and produces one. A NEON add takes two registers of four numbers each and produces four sums at once, lane by lane. A lane is one slot in a register. Each NEON register here has four.

A dot product of 288 numbers takes 72 vector multiply-adds instead of 288 scalar ones. The catch, as the next page shows, is that width does not help if every instruction waits for the previous one.

Takeaway: one NEON instruction does four lane-wise operations, so a 288-number dot product needs 72 instructions instead of 288.

How many numbers fit in the registers?

A fast kernel keeps its running sums and the numbers it is about to use in registers at the same time. An accumulator is a running sum that is updated again and again. AArch64 is ARM’s 64-bit instruction set, and the core has 32 vector registers, v0 to v31, each 128 bits. The same register can be read as 16 bytes, 8 × 16-bit, 4 × 32-bit or 2 × 64-bit numbers. For f32 work it is 4 lanes, written v0.4s in assembly (“4 singles”).

Running out of registers is costly. The kernel must spill values to memory and load them back, which costs more than it saves. That register budget decides the shape of the GEMM tile.

All 64-bit ARM cores have NEON; it is not optional, so code for aarch64 can always use it. The Snapdragon 8 Elite’s Oryon cores also have extensions on top (dot product for 8-bit integers, i8mm, bf16, fp16), but no SVE, ARM’s newer variable-width vectors.

Takeaway: the phone has 32 vector registers of four floats each, and a kernel must fit its running sums into them.

Which five instructions does the engine use?

The table gives each Rust name, the assembly instruction it becomes, and what it does. A store writes a register back to memory; a load reads memory into a register.

Rust intrinsicInstructionDoes
vdupq_n_f32(0.0)dup / movia register with the same value in all 4 lanes (here: zeros, for an accumulator)
vld1q_f32(ptr)ld1 / ldr qload 4 consecutive floats from memory
vfmaq_f32(acc, a, b)fmlaacc + a × b in every lane, one rounding
vaddq_f32(a, b)faddlane-wise add, to combine accumulators
vaddvq_f32(a)faddp ×2add the 4 lanes of one register into a single float

With just these, a dot product takes three steps: zero an accumulator; repeat “load 4 weights, load 4 inputs, fused multiply-add”; at the end, add the 4 lanes together. The attention kernel adds one more store, vst1q_f32, to write its results back to memory.

Takeaway: a NEON dot product needs only loads, fused multiply-adds and one final lane sum.

How do you call NEON from Rust?

The NEON instructions should live inside ordinary Rust code, not in a separate assembly file. An intrinsic is a Rust function that looks like a function but compiles to (usually) one specific instruction. Rust provides ARM’s standard names in std::arch::aarch64, with a type for each register shape. float32x4_t is a register of four f32 lanes. The compiler still chooses which physical registers to use and schedules the instructions; you choose the operations. This is the same API C programmers use from arm_neon.h, so ARM’s documentation applies directly.

The code below is the inner loop of the GEMV in src/kernels/neon.rs. Build it up one step at a time.

Step 1: start the running sum at zero

use std::arch::aarch64::*;

let mut acc = vdupq_n_f32(0.0);                      // [0, 0, 0, 0]
  • use std::arch::aarch64::*; brings the NEON functions and types into scope.
  • vdupq_n_f32(0.0) fills all four lanes with 0.0. The accumulator starts at zero.
  • let mut makes the variable changeable, because the loop will update it.

Step 2: multiply and add, four at a time

for j in (0..n4).step_by(4) {
    acc = vfmaq_f32(acc,
                    vld1q_f32(row.as_ptr().add(j)),  // 4 weights
                    vld1q_f32(x.as_ptr().add(j)));   // 4 inputs
}
  • (0..n4).step_by(4) visits j = 0, 4, 8, and so on, the start of each group of four.
  • vld1q_f32 loads 4 consecutive floats from memory into a register.
  • vfmaq_f32(acc, a, b) computes acc + a × b in every lane and stores the result in acc.
  • The snippet leaves out the unsafe { } block these calls sit in (see the next section).

Step 3: add the lanes and handle the leftovers

let mut s = vaddvq_f32(acc);                          // lanes → one float
for j in n4..n { s += row[j] * x[j]; }                // leftovers, one by one
  • vaddvq_f32 adds the four lanes of acc into one float.
  • The second loop handles the elements left over, one at a time, with ordinary scalar code.

All three steps together

use std::arch::aarch64::*;

let mut acc = vdupq_n_f32(0.0);                      // [0, 0, 0, 0]
for j in (0..n4).step_by(4) {
    acc = vfmaq_f32(acc,
                    vld1q_f32(row.as_ptr().add(j)),  // 4 weights
                    vld1q_f32(x.as_ptr().add(j)));   // 4 inputs
}
let mut s = vaddvq_f32(acc);                          // lanes → one float
for j in n4..n { s += row[j] * x[j]; }                // leftovers, one by one

The leftover elements that do not fill a whole register are the tail, and they are where SIMD bugs like to live.

Takeaway: each intrinsic is one NEON instruction, and the tail needs ordinary scalar code.

Why does a NEON load need unsafe?

vld1q_f32 takes a raw pointer, which is a memory address with no length attached. It reads 16 bytes from that address and does not check how long your array is. Take a row of 8 floats. A load at j = 4 reads floats 4 to 7, which is fine. A load at j = 6 would read floats 6 to 9, and floats 8 and 9 lie past the end. The read would return garbage at best and crash at worst. Rust cannot check this, so the call must be inside an unsafe block, which means: “I, the programmer, have checked this.”

The project’s rule is that every unsafe block carries a // SAFETY: comment saying why it is safe. For the loop above: “every load reads 4 floats starting at j < n4 ≤ n, inside row and x, both of length n.” The function also asserts the lengths at the top, so a wrong call panics instead of reading out of bounds. (Phase 1 explains unsafe in general.)

Takeaway: every NEON load needs a bounds argument in a SAFETY comment, because the compiler does not check it.

Does FMA round like a multiply and an add?

FMA is a fused multiply-add: a × b + c done as one instruction. vfmaq_f32 computes acc + a × b and rounds once, at the end. A separate multiply then add rounds twice. FMA is faster (one instruction) and slightly more accurate, but its results differ in the last bits from the scalar loop’s. That is one of the two reasons Phase 3 gives up bit-identity with llama2.c (the other is the order of additions, next page).

Takeaway: FMA rounds once, so compare its output with a scalar loop by tolerance, not bit for bit.

Check yourself

How many f32s fit in one NEON register, and why?

Four: the register is 128 bits and an f32 is 32 bits.

A dot product over 288 numbers with one accumulator. How many vfmaq_f32 calls, and what is left at the end?

72 calls (288 ÷ 4), no tail. At the end the accumulator holds 4 partial sums, and vaddvq_f32 adds them into one float.

Why does vld1q_f32 need unsafe?

It reads 16 bytes from a raw pointer without any bounds check. The programmer must guarantee the 4 floats exist; the SAFETY comment records why they do.

If NEON does 4 multiply-adds per instruction, why isn't step 1 four times faster than scalar?

It is roughly 3–4× (5.3 → 17.8 GB/s measured), but no more, because every FMA still waits for the previous one on the same accumulator. Width alone does not break the chain: next page.

What you should take away

A NEON register holds four floats, and one instruction works on all four lanes at once.

Each intrinsic maps to one instruction, and every load needs a bounds argument written down.

FMA rounds once, so it is faster and a little different from multiply then add.
