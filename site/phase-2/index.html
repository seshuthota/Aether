Phase 2 — a whole model in plain Rust

A language model is a program that scores each possible next token. Phase 2 builds every part of a real one, in the simplest code that works: no vector instructions, no threads, one token at a time. When it is done, a 15-million-parameter model writes children's stories on the phone, and every number it computes matches a reference program exactly.

What model is this, and how big is it?

You need a model small enough to read in full. A parameter is one learned number inside the model. stories15M is a tiny model trained by Andrej Karpathy on simple children's stories. It is small enough to understand completely and big enough to be a real transformer, the kind of network most modern language models use. It has the same parts, in the same order, as the models in Phases 5 and 7. Only the sizes are smaller.

Each row of the table is one setting. The last column says what it does.

SettingValueWhat it means
dim288Every token is a vector of 288 numbers while it moves through the model.
layers6The same block (attention, then MLP) applied 6 times, each with its own weights.
attention heads6Each layer's attention runs as 6 independent heads of 48 numbers.
hidden_dim768The MLP widens the vector to 768 numbers, then narrows it back to 288.
vocabulary32,000Tokens it knows. It outputs one score for each.
context256The most tokens it can look back over.
parameters15.2 million60.8 MB as f32 calculated — the file is 60,816,028 bytes measured.

How do you know the code is right? Compare it with a program that already is. llama2.c is one C file that runs this model. Its job here is to be the answer key. Our code is written independently, in Rust, and then compared with it number by number.

Takeaway: stories15M has the same parts as the larger models, only smaller, so you can read all of it.

How do you know it is finished?

Text that looks fluent is not proof that the code is right. The phase was finished when three things were true, all checked on the PC and on the phone:

  • For the prompt “Once upon a time”, 14 kinds of intermediate result (the embedding, each layer's q, k, v, attention output, MLP output, and so on, through to the final scores) equal llama2.c's for 6 layers × 64 positions, with an error of exactly 0 measured. An error of 0 means the two programs produce the same bits.
  • Greedy generation and seeded random sampling produce the same tokens as llama2.c, and the same text byte for byte measured.
  • The tokenizer gives the same ids as llama2.c's for 323 test strings: accents, Chinese, emoji, control characters measured.

Then one number for the record: 88.6 tokens per second on one prime core, on battery measured. llama2.c, compiled for the same phone, did 84.7. Page 12 explains why both are this slow, and why that is good news.

Takeaway: finished means the output matches the reference exactly, not that the text merely looks right.

What you should take away

A small model has the same parts as a large one: an embedding, six layers of attention and MLP, and a classifier.

Each page is one box on the path from a token to the next token, and you read them in order.

The model counts as correct only when it matches llama2.c number for number, and 88.6 tokens per second is where the speed work begins.

Measured numbers come from the iQOO 13 (SM8750) in October 2026, on battery, and are in results/ in the repo. Teal is measured, blue is calculated, amber is an assumption or an illustration.
