The phone

Once the binary exists, it still has to be copied somewhere the phone will execute it, and you have to be able to see the hardware you are about to measure. Phase 0 did that inspection. Phase 1 will use the same files as instruments.

adb

adb is how the PC talks to the phone. Two commands cover Phase 0:

  • adb push <local> <remote> copies a file to the phone.
  • adb shell <command> runs one command there, the way a single SSH command would.

This phone was attached over Wi-Fi, not USB, as 192.168.29.11 with a port. The port changed between sessions (45375, then 42065) measured. adb devices is the first thing to check when a run produces no test output.

Android adds SELinux on top of ordinary Unix permissions. Some things that work on a desktop Linux box are denied here even when the Unix mode bits look fine. The practical rule for Phase 0 is narrower than the whole of SELinux: there is one directory the shell user can both write and execute.

Where a binary may run

/data/local/tmp is that directory. The runner uses /data/local/tmp/aether. Anything copied there still needs chmod +x.

Running the same hello world from /sdcard returned Permission denied measured. /sdcard is mounted so that execution is not allowed. That is why the runner does not push to the shared storage you can see from a file manager.

Qualcomm’s product brief for SM8750 describes an Oryon CPU with prime cores up to 4.32 GHz on this version of the platform (a faster bin exists; this phone is not it) and performance cores up to 3.53 GHz. The sysfs frequencies match that bin exactly. There is no third, slower class.

The plan was too general

A generic Snapdragon story has prime, performance, and efficiency cores. This chip has no efficiency cores. One thread on a slow core dragging a parallel matmul is a real problem on older phones. Whether the 3.53 versus 4.32 split matters for bandwidth and energy is a Phase 1 question, not something to assume from the plan.

Current frequency is a different file, scaling_cur_freq. It moves. Idle cores sit slower and ramp up under load. That ramp is one reason a timing needs warm-up. Phase 0 did not catch the ramp in the sum experiment; the earlier experiments had already kept a core busy. The mechanism is still real. Phase 1 reads this file while a benchmark runs.

Feature flags that matter later

/proc/cpuinfo Features line, first core measured. The flags Phase 3 and Phase 6 will care about:

FlagPresentLater use
asimdyesBase NEON. 128-bit vector registers. Phase 3.
asimddpyesDot-product instructions. Quantized GEMV in Phase 6.
i8mmyes8-bit matrix multiply (smmla). Quantized GEMM, if the intrinsics are stable on the toolchain.
bf16yesArithmetic on bfloat16 (“brain float”) numbers: BFDOT and BFMMLA multiply bf16 pairs and add into f32, BFCVT converts f32 to bf16. Safetensors weights are often bf16; just reading them needs no special instruction.
fphp, asimdhpyesHalf precision.
sve / sve2noDo not plan SVE kernels for this phone.

The full line also includes crypto and pointer-auth flags (aes, sha2, paca, and others). They do not change the inference plan. Detect features at runtime with is_aarch64_feature_detected! when kernels start to diverge. Do not hard-code “this is an 8 Elite” into the op itself. That habit starts in Phase 3; Phase 0 only needs the idea.

Qualcomm’s brief also lists LPDDR5X, up to 5300 MHz, and up to 24 GB. It does not publish a GB/s figure, and “5300 MHz” does not by itself say whether that is the clock or the transfer rate. The ~85 GB/s figure you may see (a 64-bit bus × ~10.6 billion transfers per second) is a back-of-envelope guess to verify, not a measurement. assumption Phase 1 measures what one core and all cores actually move.

When a run goes silent

After the config change, a test run printed nothing. The config was fine. adb reported no devices. The runner cannot push, so Cargo’s output is just the failure from adb, easy to miss if you are looking for test result. Check the phone before debugging the linker path.

Files you will read again in Phase 1, already confirmed to exist as a category of interface:

  • /proc/cpuinfo — features and CPU part.
  • /sys/devices/system/cpu/cpuN/cpufreq/ — max and current frequency.
  • /sys/class/thermal/ — temperatures. Not sampled in Phase 0.
  • /sys/class/power_supply/battery/ — current and voltage. Units and sign vary by device. Not sampled in Phase 0.

Check yourself

Why /data/local/tmp and not /sdcard?

The adb shell user can write and execute under /data/local/tmp. /sdcard refused to execute the binary. The runner’s first lines create that directory, push, and chmod +x.

How many core classes does this phone have?

Two frequency classes, eight cores, one CPU part. Cores 0–5 max out at 3.53 GHz. Cores 6–7 max out at 4.32 GHz. No efficiency cores.

Which of those facts is a measurement, and which is a datasheet claim?

The frequencies, the CPU part, the feature flags, the model, and the SDK level were read off the phone. “Oryon”, the LPDDR5X line, and any cache size are from Qualcomm’s brief or launch coverage. Cache sizes were not read from sysfs in Phase 0. Do not treat them as measured until the working-set sweep shows the cliffs.

Phase 0 numbers were measured on the iQOO 13 (SM8750) in October 2026 unless tagged otherwise. Phase 1 pages were written before the measurements; the measured numbers are on What Phase 1 measured.
