Phase 4 — threads

Phase 3 made one core fast. Phase 4 spreads each matrix product across several cores. The hard part is not the arithmetic; it is that decode hands out a couple of hundred small jobs per token, and every one ends when its slowest thread does. The first threaded build was slower on eight cores than on two. Fixing that taught most of what this phase is about.

The idea in one paragraph

Keep one thread per core alive for the whole run, and hand it work by changing a counter it is watching, because starting threads or waking them through the kernel costs more than a job is worth. Split each matrix product by rows, so every row is still summed by one thread in the same order and the result does not change. Hand the rows out in small blocks, so faster cores take more and nobody waits long at the end. Put the thread that does the serial work on the fastest core. Then measure which cores are worth using, because on this phone the answer is not “all of them”.

Read in this order

  1. Threads that stay: how many jobs a token hands out, what a hand-out costs three ways, and how the pool does it with two counters.
  2. Splitting the work: rows, not pieces of rows; why equal shares failed; blocks from a shared counter; attention by head.
  3. Waiting: spin, then park: the trade between reacting fast and leaving the core free, the lost wake-up, and false sharing.
  4. Choosing cores: prime and performance cores, the caller on the fastest core, and what each core set measured.

Still open

  • The clean sweep: decode and prefill against every core set from one core to eight, twice in opposite orders, with nothing else running; the hand-out cost on the phone; and joules per token for four sets over five minutes each. It needs the phone, and its results get their own page.
  • Why cores 0–1 slow things down: the interrupt hypothesis, tested by counting /proc/interrupts per core in every run of the sweep.
  • Where the rest of the time goes: SmolLM2 on six cores reads its weights at about a third of the memory bandwidth (Choosing cores).
