Plotting the sweep

The working-set sweep produces about twenty numbers per core set. You read them as a picture: plateaus and cliffs. The phone prints the numbers, the PC saves and draws them, and both files go in results/.

From phone to picture

The phone does no drawing. It doesn’t have Python, and it shouldn’t be busy with anything but the benchmark. The PC already has Python and matplotlib 3.10 measured.

A CSV with its conditions

CSV is a table as text: one row per line, values separated by commas. Rust can print it with println!, and Python can read it without help. Put the conditions at the top as # lines, so the numbers and the circumstances that produced them can never be separated:

# sweep: pure read, f32, pinned cpu6
# date=2026-10-20 screen=off charging=no start_temp_c=31.2
# commit=5632c75
bytes,gbps
4096,88.41
8192,92.07
…
println!("bytes,gbps");
println!("{},{:.2}", bytes, gbps);

One file per core set (sweep-cpu6.csv, sweep-cpu0.csv, sweep-cpu0-5.csv) keeps each run complete on its own. The numbers above are an example of the format, not results.

Why the size axis is logarithmic

The sweep doubles the size each step: 4 KB, 8 KB, 16 KB … 256 MB. That is 17 sizes spanning a factor of 65,536. On an ordinary axis the first twelve points, everything up to 8 MB, crowd into the left 3% calculated, which is exactly where the L1 and L2 cliffs are.

Same points, two axes

An illustrative curve with the shape from the Bandwidth page, not data from this phone.

On a log axis, every doubling is the same distance, so each cache level gets room in proportion to how many doublings it covers. The y axis stays linear: you want to read GB/s directly and see that DRAM is a fraction of L1.

The plotting script

This goes in tools/, where host-side Python lives. Give it one or more CSV files and it draws them on the same axes:

# Plot one or more sweep CSVs (bytes,gbps) on the same axes.
# Usage: python3 tools/plot_sweep.py results/sweep-cpu6.csv results/sweep-cpu0-5.csv
import csv
import sys
from pathlib import Path

import matplotlib
matplotlib.use("Agg")                      # write a file; no window needed
import matplotlib.pyplot as plt
from matplotlib.ticker import FuncFormatter


def size_label(b, _pos):
    return f"{b / 2**10:.0f} KiB" if b < 2**20 else f"{b / 2**20:.0f} MiB"


fig, ax = plt.subplots(figsize=(8, 4.5))
for path in sys.argv[1:]:
    with open(path) as f:
        rows = list(csv.DictReader(line for line in f if not line.startswith("#")))
    x = [int(r["bytes"]) for r in rows]
    y = [float(r["gbps"]) for r in rows]
    ax.plot(x, y, marker="o", label=Path(path).stem)

ax.set_xscale("log", base=2)               # each step right = twice the size
ax.xaxis.set_major_formatter(FuncFormatter(size_label))
ax.set_xlabel("working set")
ax.set_ylabel("read bandwidth (GB/s)")
ax.set_ylim(bottom=0)
ax.grid(True, alpha=0.3)
ax.legend()
fig.tight_layout()
fig.savefig("results/sweep.png", dpi=150)
print("wrote results/sweep.png")

Tested on made-up CSVs, including Windows-style line endings measured. Run it from the project root so results/ resolves.

  • DictReader uses the header line, so columns are found by name, not position.
  • The # lines are skipped before the CSV reader sees them.
  • set_ylim(bottom=0) keeps the y axis from starting at, say, 10 GB/s, which would make a small drop look like a cliff.
  • A dot on every measured point shows where data exists. A line between two dots is not a measurement.

Bytes and gigabytes

The sizes are powers of two: 4096 bytes, 1,048,576 bytes. Those are KiB and MiB, which is how the script labels them. Bandwidth is the other convention: GB/s means 109 bytes per second, which is what the decode ceiling and published figures use. Both are fine. Mixing them silently is a 7% error at the gigabyte scale (230 / 109 ≈ 1.074) calculated.

So the Rust side computes gbps = bytes_read as f64 / seconds / 1e9, and the header says gbps. Put it in a comment line too, if you like. Next month you won’t remember.

Check yourself

Why do the conditions go inside the CSV, not in a separate notes file?

Files get copied, renamed and compared months later. A number separated from “which core, screen on or off, how hot” can’t be compared with anything. Inside the file, they travel together.

On a linear axis, where is the 8 MB point if the axis ends at 256 MB?

At 8/256 ≈ 3% of the width. Everything from 4 KB to 8 MB, which covers both L1 and L2, fits in that 3%.

A plateau sits at 45 “GB/s” computed with 230. What is it in the site’s units?

45 × 1.074 ≈ 48.3 GB/s (109). Pick one convention and say which.
