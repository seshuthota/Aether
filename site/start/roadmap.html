The phases

From From_Scratch_Android_Inference_Engine_Plan.md, which is the source of truth. Effort is the plan’s rough guess, not a deadline.

  1. Phase 0 — setup done

    Cross-compile Rust for the phone, run cargo test there, time code without fooling yourself, and store a tensor as a flat buffer.

    Done when: a test runs on the phone and reports back to the PC.

  2. Phase 1 — hardware and the memory model reading

    Caches, memory bandwidth, cores, alignment, the roofline, power and heat. Measured, not looked up.

    Done when: a results table of cache and DRAM bandwidth, one core vs all, hot vs cold, and joules per GB, that you can explain. Phases 0–1 together: 1–2 weeks.

  3. Phase 2 — a real tiny model, scalar

    stories15M end to end in plain Rust: loader, tokenizer, every layer operation, KV cache, generation loop.

    Done when: the text on the phone is token-for-token identical to llama2.c. 2–3 weeks.

  4. Phase 3 — NEON kernels

    Rewrite matrix × vector (and matrix × matrix for prefill) with ARM’s vector instructions.

    Done when: same tokens, a measured speed-up, and an explanation of how close GEMV gets to single-core bandwidth. 2–4 weeks.

  5. Phase 4 — threads and cores

    A thread pool pinned to chosen cores; tokens per second and energy per token against thread count.

    Done when: you can explain the speed-vs-threads curve and the energy-vs-core-set trade-off. 1–2 weeks.

  6. Phase 5 — a modern architecture

    SmolLM2-135M: safetensors, memory-mapped weights, grouped-query attention, byte-level BPE tokenizer.

    Done when: output matches Hugging Face, and the tokenizer matches exactly. 2–4 weeks.

  7. Phase 6 — quantization

    Q8_0 and Q4_0 weights, integer dot-product kernels, and measuring how much accuracy the fewer bits cost.

    Done when: perplexity and KL divergence match llama.cpp on the same file. 3–6 weeks.

  8. Phase 7 — a real small model

    Qwen2.5-0.5B from a GGUF file, its tokenizer and chat template, and a full benchmark suite including sustained and energy numbers.

    Done when: usable chat on the phone, with a written explanation of where the time and energy go. 3–5 weeks.

  9. Phase 8 — Android app

    A C interface, a thin JNI layer, a small Kotlin app that streams tokens.

    Done when: an installable APK streams a chat reply at the same speed as the command-line binary.

After that, optional directions: better quantization formats, GPU kernels with Vulkan, speculative decoding, the NPU.

Rules that hold the whole way

  • Do not skip ahead. Each phase’s measurements are what the next one is compared against.
  • Correctness comes from outside. numpy, llama2.c, Hugging Face and llama.cpp produce the golden outputs. Never a second copy of our own code.
  • A phase is done when you can explain the numbers, not when they hit a target. 40% of bandwidth with an explanation is finished.
  • Write notes/phase-N.md in your own words at the end of each phase. This site is the reference. The journal is the proof you understood it.

Phase scope and effort come from the plan. Status reflects the repo as of the Phase 0 commit.
