The roadmap

Nine phases, each small enough to understand completely before the next. This page is the map, not the territory: one line per phase about what it is for. The explanations are written when that phase is the one being learned.

What parts does the engine have?

Which part of the engine belongs to which phase? A kernel is a small routine that does one heavy job, such as a matrix multiply. Pick a phase to see which parts it builds. Most parts get built once simply, and then rebuilt later to be faster or more general.

In what order do the phases go?

Each phase builds on the one before it. The plan is the source of truth, and effort is its rough guess, not a deadline. Each item ends with a Done when line, the test for moving on.

  1. Phase 0 — setup built, notes written

    Cross-compile Rust for the phone, run cargo test there, time code without fooling yourself, and store a tensor as a flat buffer.

    Done when: a test runs on the phone and reports back to the PC.

  2. Phase 1 — hardware and the memory model built, notes written

    Caches, memory bandwidth, cores, alignment, the roofline, power and heat. Measured, not looked up.

    Done when: a results table of cache and DRAM bandwidth, one core vs all, hot vs cold, and joules per GB, that you can explain. Phases 0–1 together: 1–2 weeks.

  3. Phase 2 — a real tiny model, scalar built, notes written

    stories15M end to end in plain Rust: loader, tokenizer, every layer operation, KV cache, generation loop.

    Done when: the text on the phone is token-for-token identical to llama2.c. 2–3 weeks.

  4. Phase 3 — NEON kernels built, notes written

    Rewrite matrix × vector (and matrix × matrix for prefill) with ARM’s vector instructions.

    Done when: same tokens, a measured speed-up, and an explanation of how close GEMV gets to single-core bandwidth. 2–4 weeks.

  5. Phase 4 — threads and cores built, notes written

    A thread pool pinned to chosen cores; tokens per second and energy per token against thread count.

    Done when: you can explain the speed-vs-threads curve and the energy-vs-core-set trade-off. 1–2 weeks.

  6. Phase 5 — a modern architecture built overview written

    SmolLM2-135M: safetensors, memory-mapped weights, grouped-query attention, byte-level BPE tokenizer. The overview is written; the topic pages are still to write.

    Done when: output matches Hugging Face, and the tokenizer matches exactly. 2–4 weeks.

  7. Phase 6 — quantization built notes started

    Q8_0 and Q4_0 weights, integer dot-product kernels, and measuring how much accuracy the fewer bits cost. Written: the overview and three topic pages.

    Done when: perplexity and KL divergence match llama.cpp on the same file. 3–6 weeks.

  8. Phase 7 — a real small model built notes started

    Qwen2.5-0.5B from a GGUF file, its tokenizer and chat template, and a full benchmark suite including sustained and energy numbers. Written: the overview, GGUF and NEON attention, measured honestly.

    Done when: usable chat on the phone, with a written explanation of where the time and energy go. 3–5 weeks.

  9. Phase 8 — Android app built overview written

    A C interface, a thin JNI layer, a small Kotlin app that streams tokens. The overview is written.

    Done when: an installable APK streams a chat reply at the same speed as the command-line binary.

After that, optional directions: better quantization formats, GPU kernels with Vulkan, speculative decoding, the NPU.

Takeaway: the phases run in order, and each one ends with a Done when line you must meet.

What rules hold the whole way?

These four rules apply to every phase, not just one.

  • Do not skip ahead. Each phase’s measurements are what the next one is compared against. Skip one and the next has nothing to compare with.
  • Correctness comes from outside. numpy, llama2.c, Hugging Face and llama.cpp produce the golden outputs. Never a second copy of our own code, because a copy would share our bugs.
  • A phase is done when you can explain the numbers, not when they hit a target. 40% of bandwidth with an explanation is finished.
  • Write notes/phase-N.md in your own words at the end of each phase. This site is the reference. The journal is the proof you understood it.

Takeaway: go in order, check against outside references, and explain the numbers before moving on.

What you should take away

The engine is built in parts, and each phase adds some of them.

A phase is finished when its Done when line holds and you can explain the numbers.

Use the outside references for every check, and keep your own notes as the proof.

Phase scope and effort come from the plan. Status reflects the repo on 2026-10-24: the engine is built through Phase 8; the notes cover Phases 0–4 in full, and Phases 5–8 with an overview each plus the first topic pages.
