# Media on the devices, phone, 2026-11-26

iQOO 13 (SM8750, Adreno 830, Hexagon), on battery (84 %), screen on,
SoC 35–41 °C. aether-infer `multimodal-devices` at f8ec824 plus the
uncommitted pipeline cache (QxKernels) and the CLI's transcribe on the
GPU / DSP; `aether` built with `vulkan,hexagon`. CPU runs: the CLI's
default cores (one thread per core, 8). Q4_K_M LMs, Q8_0 mmprojs.

## LFM3-VL, one image (scene.png, 1024 patches → 256 tokens; 275-token prompt)

| backend | prompt (encoder + LM) | decode |

| CPU | 2.43 / 2.29 / 2.22 s | 44.5 / 42.7 / 47.7 tok/s |
| GPU (before the pipeline cache) | 6.58 s | 34.6 tok/s |
| GPU, CPU decode (before the cache) | 7.11 s | 42.8 tok/s |
| GPU | 4.56 / 4.64 s | 30.3 / 32.5 tok/s |
| DSP (encoder on the CPU) | 3.83 s | 25.2 tok/s |

Same reply text on every route. Text only, 253 tokens: GPU 2.68 s, CPU
1.11 s (the LM's prompt on the Adreno is 2.4x slower than the CPU's).

GPU encoder, `AETHER_GPU_PROFILE=1` (each stage its own submission):
blocks 593–625 ms (attention 166–172, gate_up 134–154, down 73–74, conv
in 61–64, quant 48–50, norm 27, conv out 21–25, qkv 22, conv 3x3 16–17,
qk 8–9, attn out 13); patch embedding on the CPU 8 ms. Making the
encoder: 3428 ms with one qx_gemm_q8 pipeline per product (about 47 ms
each, 58 products), 688 ms with one pipeline per (type, accum).

## What it says

- The encoders are faster on the Adreno than on the CPU (LFM3-VL's
  about 0.6 s against about 1.2 s), but LFM3's LM is slower there (prompt
  2.4x, decode about 30 %), so whole requests are slower on the GPU route.
- The DSP is the fastest and steadiest LM for LFM3-Audio's ASR, and close
  to the CPU for LFM3-VL's image prompt (its encoder on the CPU).
- The best split on this phone would be the encoders on the GPU and the
  LM on the CPU or the DSP: not a route the API has yet.
