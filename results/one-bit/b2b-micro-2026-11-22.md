# B2b micro-benchmarks: Q1_0 decode kernels

aether-infer `one-bit` (B2b), iQOO 13, single core 7 unless stated, 8B
`attn_q` 4096×4096 (2,359,296 weight bytes) with the model's real Q1_0
bytes. `kquant_bench` measures one `linear` call (activation quantization
included); `--ab` times the kernel on the same bytes. Caps are noted per
table; the A/B pairs below were run back to back in one session.

## H1: transposed bit planes (kept)

Per 128-weight block, the file layout expands each sign byte with `tbl`,
`cmtst` and `orr` before `sdot`; the transposed layout is one 16-byte load
and eight `cmtst` against `1 << k`, then eight `sdot` (no `tbl`, no `orr`).
The missing `+1` terms are the activation sums, `sum(sign·q) =
−2·sdot(mask, q) − sum(q)`.

| kernel, 2.40/2.44 GHz | file layout | transposed | change |
| --- | --- | --- | --- |
| `dot4` t=1, single core | 603.8 µs / 3.91 GB/s | 527.8 µs / 4.47 GB/s | +14.4 % |
| `mmla4` t=8, single core | 1346.6 µs / 14.02 GB/s | 1277.3 µs / 14.78 GB/s | +5.4 % |
| `linear`, t=1, one thread | 616.2 µs / 3.83 GB/s | 543.1 µs / 4.34 GB/s | +13.5 % |
| `linear`, t=1, 6 threads | 171.7 µs / 13.74 GB/s | 153.4 µs / 15.38 GB/s | +11.9 % |

Full `linear`, t=1, 6 threads, same step: 176.9 → 153.4 → **133.4 µs**
for original → H1 → H1+H2 (+24.6 % overall, +13.0 % from H2); single
thread 616.2 → 543.1 → **460.5 µs** (+25.3 % overall, +15.2 % from H2).
The H2 step is also measured paired against H1 at 2.40/2.44 below.

The gate (+10 % on the 4096×4096 GEMV) is passed. The prompt path gains
less because `smmla` already amortizes over tokens; it still drops the
`tbl` per quarter.

## H2: reuse across rows (kept)

The `+1` term is the same for every group of four rows, so `q8_0_sums`
computes `Σq` once per matvec and `dot4_q1_0t_q8_0_sums` reuses it. The
kernel body no longer runs two `vaddlvq_s8` per quarter per row group.

| 2.40/2.44 GHz, 4096×4096 | H1 | H1+H2 | change |
| --- | --- | --- | --- |
| single t=1 | 591.7 / 590.6 µs, 9.02 ns/256 | 515.6 / 500.3 µs, 7.75 ns/256 | **+16.4 %** |
| 6 threads t=1 | 172.8 / 173.6 µs, 2.64 ns/256 | 146.2 / 146.8 µs, 2.24 ns/256 | **+18.2 %** |
| single t=8 (`mmla4`) | 1524.9 / 1530.6 µs | 1528.6 / 1537.3 µs | unchanged |

8-row tiles were not implemented. After H2 the only per-quarter shared
work is one scale multiply and one vector FMA for the sum term: sharing
those over 8 rows saves about 2 of ~28 instructions per block per row
(~7 %), while the tile needs 8 accumulators, 8 weight-vector registers and
8 scale registers; the target was already met, so it was dropped.

## H3: static vs dynamic row split (already dynamic)

`ThreadPool::for_blocks` already hands out row blocks from an atomic
counter; a temporary build with `for_blocks` replaced by `for_ranges`
(equal contiguous shares) measured, 3 alternated cooled rounds, 6 threads,
2.40/2.44 GHz:

| decode tg64, 2.40/2.44 GHz | dynamic | static | change |
| --- | --- | --- | --- |
| Bonsai 1.7B Q1_0 | 53.88 | 44.07 | **+22.3 %** |
| Gemma 4 E2B Q4_0 | 34.95 | 34.49 | +1.3 % |

Dynamic is kept (it was already the default); the static build was
reverted. The Q1_0 kernel is ALU-bound and its per-op time is short, so
an even split waits for the slow cores; Gemma's decode is bandwidth-bound
and barely notices.

## H4: bit-plane activations (not tried)

A popcount formulation can only compute `sign(w)·sign(x)` (128 MACs as two
`xor` + two `cnt`), i.e. it needs 1-bit activations. The model is checked
against Q8_0 activations and the KL base; changing the activation
precision would not be the same model. Keeping Q8 activations and
popcounting each bit plane costs more than `sdot` (16 multiply-adds per
instruction). Not implemented, per the gate.
