# B4 Phase 1: Q1_0 GEMV on the Adreno (2026-11-22)

The decision gate for a Qwen3 GPU path: how many Q1_0 weight bytes a second
the phone's Adreno can stream through an int8 matrix-vector product, on the
8B Bonsai's real matrices, against the CPU's `dot4_q1_0t_q8_0` kernel at the
same clock step.

- GPU: Adreno 830 (Snapdragon 8 Elite), Vulkan 1.3.284, driver
  `0x80320050`, subgroup 64 lanes, `VK_KHR_shader_integer_dot_product`
  (int8 dot), `VK_KHR_8bit_storage`, `VK_KHR_16bit_storage`,
  `VK_KHR_shader_float16_int8`, subgroup arithmetic / ballot / shuffle /
  shuffle-relative / rotate, `VK_EXT_subgroup_size_control`.
- Kernel: `qx_gemv_q8.comp` FMT 41 (new). Q1_0 keeps its file bytes; a
  32-value piece is the block's four-byte bit word, whose bit `p` is weight
  `32i + p`. A nibble becomes four `0x01`/`0xFF` (+1/−1) bytes with IMAD +
  AND + IMAD + IADD, then `OpSDot` against the Q8_0 activations
  (`quant_x.comp`), 4 rows a workgroup, 32 lanes a row group.
- Correctness: on every shape the GPU's output matches the CPU's on the
  same Q8_0 codes within **5.2e-7** relative (the integer sums are equal;
  only f32 accumulation order differs). The golden test
  `q1_0_gemv_q8_matches_gguf_py` (six cases from `tools/gen_q1_0.py`) also
  passes on the PC's Intel GPU.
- Device limits from `vk_bandwidth` on the same phone: 64-lane subgroups, max
  workgroup 1024, 32 KB shared memory, timestamp period 52.08 ns, a 15.1 GB
  device-local heap and a 4 GB one; a plain read shader reaches **66–68 GB/s**
  at 4–64 MB (57.3 GB/s at 256 MB; copies 65–72 GB/s). The Q1_0 kernel's
  26.0 GB/s cold is 39 % of that read ceiling, and its 22 GB/s sustained
  33 %, so it is **ALU-bound, not stream-bound**: the 8 nibble expansions
  and 8 `OpSDot`s a 32-value piece are the cost.
- `bench/examples/vk_q1_0.rs`: for each shape, the CPU arm (`linear_on`,
  transposed Q1_0, 6 threads cores 2–7) and the GPU arm; GPU timestamps
  around back-to-back dispatches (median of 5 after 0.3 s of warm-up),
  then a 30 s sustained run by wall clock. The model is the real 8B Q1_0
  file; the model's matrices are the source of the bytes.

Conditions: one job, start 40 °C SoC / 38.9 °C board, caps 2.40/2.44 GHz,
battery 60 %; end 48 °C / 43.6 °C, caps 1.79/1.96 GHz. During the run the
GPU zone went from 44 to 64.6 °C and the board from 38.9 to 43.4 °C, and
the vendor dropped the CPU caps twice as it heated.

## Per shape

`cold` is the timed median (each shape after a short warm-up); `sustained`
is 30 s of the same dispatch. CPU GB/s is the same-shape `linear_on` arm
with the model's transposed layout.

| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| attn_k (k+v) | 1024 × 4096 | 72 | 0.59 MB | 14.14 | 17.67 | 14.55 | 1.25× |
| attn_q (q+o) | 4096 × 4096 | 72 | 2.36 MB | 16.57 | 24.95 | 22.00 | 1.51× |

The CPU column is the same kernel the model runs (`dot4_q1_0t_q8_0` with
the shared activation sums); on the host the example's CPU arm is the
portable scalar kernel, so only the phone's column is comparable.

## Whole-pass estimate

Summing the measured GPU GEMV times over the model's matrices (36 layers ×
[q, k, v, o, gate, up, down] + the classifier), 1,064,109,888 bytes:

| | time per token | tok/s | weight GB/s |
| --- | ---: | ---: | ---: |
| GPU, cold matrices | 40.95 ms | **24.42** | 26.0 |
| CPU, same shapes (sum) | 67.30 ms | 14.86 | 15.8 |
| CPU, whole 8B decode (Phase A) | 68.31 ms | **14.64** | 15.6 |

The CPU sum is the example's per-shape arm (which reads 15–17 GB/s per
shape); the whole-model number is the measured decode, which includes
attention, norms, the embedding lookup and 36 layers of dispatch. The GPU
estimate is **matrix-only**: a real GPU decode would add those stages and
the per-layer launches, so 24.42 is an upper bound.

## Gate

The gate asked for **≥ ~25 tok/s** (≈29 GB/s) of matrix-only decode, i.e.
~1.5× the CPU's top-step 16.53 tok/s. Measured: **24.42 tok/s**, 2.3 %
under, and **1.67× the CPU at the same (2.40/2.44 GHz) clock step**
(14.64 tok/s), or 1.48× the top-step CPU number. Sustained, the GPU
settles at 21–23 GB/s (22.0–22.8 across the shapes) as the GPU and board
heat, i.e. about 85 % of the cold rate.

So the GPU is faster than the CPU on every shape and by 1.5–1.8× on the
matrix products, but the whole-model estimate lands just short of the
absolute gate and inside the 1.0–1.5× band against the top-step CPU. Per
the gate's rule this is a **report-and-decide** outcome, not a build.
