# B3 on the phone: Bonsai 4B and 8B Q1_0, correctness and memory

aether-infer `one-bit` `accd54d` (engine source `0e071bb`), iQOO 13
(I2401), cores 2–7, 6 threads, on battery. The KL runs are **correctness
runs, not benchmark rounds**; the cool-down before each is phone_ab's
standard one, but the 18.0 s / 32.1 s below are incidental, not speed
records (speed is in `b3-phone-speed-2026-11-22.md`).

## KL against llama.cpp

wikitext-2, 2 chunks of 512, against the base files written on the PC by
`llama-perplexity --kl-divergence-base` on the same GGUFs.

| | 4B | 8B |
| --- | --- | --- |
| PPL (Aether, phone) | 14.536940 ± 2.275753 | 13.167487 ± 2.017533 |
| PPL (base) | 14.355021 | 13.046527 |
| **Mean KLD** | **0.000169** | **0.000186** |
| Same top token | 99.216 % | 98.824 % |
| 510 tokens scored | 18.0 s | 32.1 s |
| PC KLD for comparison | 0.000188 | 0.000192 |

The phone's NEON kernels are slightly closer to llama.cpp than the PC's
scalar path on the 4B (0.000169 against 0.000188); the 8B is 0.000186
against 0.000192. Both are at B2's 1.7B level (0.000264) and well below
Qwen3 1.7B Q8_0's 0.0020.

## Greedy and the 8B's separate classifier

"The capital of France is", `--temp 0`, 24 tokens. Both models print:

> Paris. Paris is the capital of France. Paris is the capital of France.
> Paris is the capital of France. Paris

which is byte-identical to `llama-completion --no-conversation` on the host
for both files. The 8B's `output.weight` is a separate Q1_0 tensor (not
tied); this run confirms the phone uses it.

## Memory

`aether run -c 512 -n 24`, peak RSS reported by the engine: **757,072 kB**
(4B) and **1,246,896 kB** (8B). The f32 KV cache is 36 layers · 8 kv heads
· 128 · 2 · 4 B · 512 ≈ 151 MB; the mapped Q1_0 file is 540 MiB / 1.07 GiB.
