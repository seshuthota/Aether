# P4: queued submissions (2026-11-21)

Branch `prompt-speed-2` (aether-infer): `profile-p6a3` (HEAD `1c56478`, one
wait per layer) against `profile-p4` (the same plus queued submissions).
iQOO 13 (SM8750, Adreno 830), Gemma 4 E2B Q4_0, on battery, screen on,
wireless adb. `scripts/phone_ab.py`, 3 rounds, alternated, cooled before
each run. Round 0 ran at 2.40/2.44 GHz caps (38–42 °C), rounds 1–2 at
2.00/2.25 (40–44 °C, battery 59–61 %). Raw:
`p4-phone-2026-11-21.txt`, `p4-1024-phone-2026-11-21.txt`.

## The change

`GemmaGpu::forward_batch` still records one command buffer per layer (a
whole pass in one buffer is what the PC's Intel GPU watchdog stopped), but
submits without waiting and waits only when four are in flight.
`Gpu::submit_async`/`wait` are new, and every command buffer ends with a
compute→compute barrier so the next submission's reads see this one's
writes. The CPU's recording now runs while the GPU works. Queueing all 37
at once lost the PC's Intel RPL-P device ("timestamps: the logical device
has been lost"); four deep is the shipped bound.

The fusions P4 listed were already there: q/k/v norm + RoPE + cache store
(`qkv_norm.comp`), post-attention/FFN norm + residual (`norm_add.comp`),
the gated GELU/SiLU (`geglu.comp`). GeGLU still writes f32 and `down`'s
`quant_x` is a separate dispatch: measured at ~1.5 % of the pass, left.

At the lower 2.00/2.25 GHz caps (rounds 1–2, medians): 512 261.9 / 273.0 →

the gain is the overlap, not faster shaders.

The 1024-token checkpoint (≥ 300 tok/s), 3 alternated rounds at
2.00/2.25 GHz caps, battery 57–58 %: old 270.08 / 267.62 / 265.05 (median

306.8) put 1024 at ~310–330, so the checkpoint holds there; the battery
held the vendor cap at 2.00 for this session, so it was not measured
directly.
