## The encoder stream

`AudioEncoder::stream()` + `stream_push(features, is_final)` in
`crates/aether/src/model/lfm3_audio.rs`: the last complete token's 8 mel
frames stay as the downsampler's left context, the 7-frame lookahead is
`(num_frames + 7 if final) / 8`, and the LFM stack carries its causal state
(conv caches, window-32 keys). The stack already trims its keys and keeps
the conv taps, so the context is bounded.

```
cargo test --release -p aether-infer --lib \
  model::lfm3_audio::tests::lfm3_audio_encoder_stream_matches_the_whole \
  -- --nocapture --test-threads=1
```

Result: all 4 ASR clips, one push and uneven chunks (100, 1, 7, 8, 9 frames):

```
clip 0: 1099 frames, one push 1.3e-6, 41 pushes + final 1.2e-6
clip 1: 1042 frames, one push 1.1e-6, 41 pushes + final 1.1e-6
clip 2: 655 frames, one push 6.8e-7, 26 pushes + final 6.8e-7
clip 3: 423 frames, one push 7.1e-7, 16 pushes + final 7.1e-7
```

The whole-clip rows are the reference's (H2/H3 hold them to 1e-4 with the
F16 mmproj). The stream reproduces them to 1.2e-6.

A first version sliced the kept frames by values instead of by `mels`,
shifting the downsampler; it showed as 0.59 of the largest row at the first
100-frame boundary, and the test caught it.

## `TranscribeStream`

Not wired for `Speech::Chat`: it still re-runs `Transcribe` on the whole
prefix. Using the encoder stream in ASR needs the chat path (`chat_audio`,
`PromptImage`/`Media::Audio`) to accept precomputed projector rows, an
`api.rs` change (asked the user; the repo's rule is to stop before one).

## llama.cpp's mtmd (second reference)

`llama-mtmd-cli` from `~/llama.cpp/build-nodl` (`d02b4c0d6`), the Q4_K_M LM
and the Q8_0 mmproj:

```
LLAMA=~/llama.cpp/build-nodl/bin/llama-mtmd-cli
GG=hostdata/lfm3-audio/gguf
$LLAMA -m $GG/LFM3-Audio-2B-Q4_K_M.gguf --mmproj $GG/mmproj-LFM3-Audio-2B-Q8_0.gguf \
  --audio hostdata/lfm3-audio/clips/jfk.wav -p "Perform ASR." -n 64 -t 8
$LLAMA ... --audio .../librispeech-1.wav -sys "Perform ASR." -p " " -n 64 -t 8
```
